# الخطة الاستراتيجية والتنفيذية — مساعد صفوان الذكي (SAFWAN AI)

**الإصدار:** 1.1 (مراجعة وتوثيق في المستودع)  
**التاريخ:** 2026-11-02  
**المالك:** صفوان  
**الحالة:** مرجع تخطيطي؛ التنفيذ يخضع لاختبارات القبول  
**النطاق:** مساعد شخصي **ووكيل تنفيذي** خاص بالمستخدم، وليس مجرد روبوت دردشة، ولا نظامًا لتقليد صوته أو شخصيته.

## 1. الرؤية ومبادئ التصميم

تطوير مساعد ووكيل ذكاء اصطناعي شخصي يفهم احتياجات مالكه، ويستفيد من المعرفة والذاكرة والأدوات لينجز أعمالًا رقمية حقيقية: **يفهم → يخطط → ينفذ → يتحقق → يصحح → يقدم نتيجة موثقة**.

- الأولوية لإنجاز العمل بدقة وجودة، لا محاكاة أخطاء المستخدم أو أسلوبه حرفيًا.
- الاستخدام شخصي، مع عزل بياناته وأسراره عن الأطراف الأخرى.
- يتعلم من المحادثات وتصحيحات المستخدم **عبر آلية حفظ وانتقاء معتمدة**، وليس بافتراض أن النموذج يُعاد تدريبه تلقائيًا.
- الاعتماد على نموذج جاهز، واسترجاع المعرفة (RAG)، وذاكرة منظمة، وأدوات تنفيذ، بدلاً من تدريب نموذج أساسي من الصفر.
- صلاحيات وحدود التشغيل تضبط من الإعدادات، مع موافقات خاصة للعمليات الحساسة.
- المشروع الحالي في GitHub هو نقطة الانطلاق؛ لا نبدأ مشروعًا مكررًا.

## 2. الواقع الحالي (دليل أولي من README في 2026-11-02)

المستودع: `safwan5001-source/safwan-smart-assistant`.

يصف `README.md` واجهة تجريبية **محلية أولًا** (PWA عربي RTL) تضم المحادثات والمهام والملفات والبحث والإعدادات، مع مصفوفة صلاحيات مطبقة في طبقة الأوامر وAPI. كما يذكر تجربة متصفح قراءة فقط، مطفأة افتراضيًا.

ويصرّح README أن **مزود النماذج، وتنفيذ الأوامر على الخادم، والتكاملات الخارجية، والحساب والمزامنة، والمكالمات، وWindows السحابي ليست مفعلة بعد**. توجد وثائق معمارية وتنفيذ وأمان ونشر، لكن وجودها لا يثبت تشغيل جميع القدرات.

**قيد التحقق:** هذه قراءة وثائقية أولية وليست نتيجة اختبار إنتاج أو فحص شامل للكود؛ لا تُعد الميزات مكتملة حتى تجتاز اختبارات فعلية. يجب مطابقة README مع الكود والنشر الحالي قبل إغلاق مهام التقييم.

## 3. البنية المستهدفة

1. **طبقة التفاعل:** دردشة وصوت ومهام وإشعارات، مع واجهة ملائمة للهاتف.
2. **طبقة العقل والتخطيط:** نموذج، فهم الأهداف، تقسيم العمل، اختيار الأدوات، التحقق من المخرجات.
3. **طبقة الذاكرة:** ملفات تعريف، سياسات، تفضيلات، معلومات عمل، قرارات، أخطاء وتصحيحات، ذاكرة المهام.
4. **طبقة المعرفة:** استيعاب المستندات، فهرسة واسترجاع مع مصادر وتواريخ وصلاحيات وتحديثات.
5. **طبقة التكامل والتنفيذ:** موصلات رسمية، محرك مهام طويل/متعدد الخطوات، حالات وإعادة محاولة آمنة، عدم تكرار التنفيذ.
6. **طبقة الحوكمة:** صلاحيات وموافقات وسجل تدقيق وعزل أسرار وبيانات وقياسات جودة وتكلفة.

## 4. كيف يتعلم المساعد بسرعة وبطريقة صحيحة؟

- **محادثاتك:** استنتاج قواعد مرشحة وتفضيلات، ثم مراجعتها قبل حفظ الدائم؛ لا تحفظ كل رسالة تلقائيًا.
- **أمثلة أعمالك:** عشر مهام حقيقية كبداية، مع المدخلات الصحيحة والنتيجة المرجعية والتصحيح إن وجد.
- **المستندات:** عقود وإجراءات وفواتير وكشوف تُفهرس مع المصدر والتاريخ، ولا تُخلط البيانات القديمة بالحالية.
- **الأنظمة المرتبطة:** جلب أرصدة وفواتير وحالات آنية من مصدرها عند الطلب، لا الاعتماد على ذاكرة قديمة.
- **نتائج التنفيذ:** تحويل الإجراءات الناجحة والتصحيحات المعتمدة إلى قواعد عمل واختبارات انحدار.

تصنيف الذاكرة: (أ) حقائق ثابتة نسبيًا؛ (ب) تفضيلات وقواعد وافق عليها المالك؛ (ج) معرفة موثقة بالمصدر؛ (د) حالة تشغيلية مؤقتة؛ (هـ) سجل مهام. لكل سجل مصدر، وتاريخ، وصلاحية وصول، وحالة اعتماد، وآلية تعديل وحذف.

## 5. مراحل التنفيذ ومعايير القبول

| المرحلة | نطاق العمل | شرط الاكتمال |
|---|---|---|
| P0 — تدقيق الأساس | حصر الكود والبيئة وAPI والصلاحيات والذاكرة الحالية | تقرير موثق بالأدلة؛ فصل يعمل/تجريبي/مخطط |
| P1 — ذاكرة مستمرة | تخزين آمن، مراجعة حفظ، استرجاع، تعديل، حذف، مصدر وتاريخ | اختبارات نجاح عبر جلسات مختلفة، وعدم تسريب أو استرجاع بيانات محذوفة |
| P2 — تعلم الإجراءات | 10 أمثلة عمل، تعليمات تشغيل واختبارات مرجعية | قياس الدقة، وتوثيق الأخطاء والتصحيحات |
| P3 — التكامل الأول | ربط محدود للقراءة بأَوْج، ثم البريد/Drive/GitHub حسب الحاجة | اختبار وصول وصلاحيات وبيانات صحيحة من المصدر |
| P4 — التنفيذ المراقب | إنشاء مسودة فعلية، مقارنة، تحقق، موافقة، تدقيق | إنجاز مهمة end-to-end دون تجاوز صلاحيات، مع إثبات نتيجة |
| P5 — التوسع | رسائل ومكالمات مرخصة، جدولة، وكلاء متخصصون عند الحاجة | اختبارات خصوصية وأمان وجودة وكلفة وتشغيل مستقرة |

ترتيب الأولويات قابل للتعديل بناءً على نتائج P0؛ لا يُفترض إنجاز مرحلة لمجرد وجود كود أو شاشة.

## 6. صلاحيات وضوابط

- **قراءة:** الوصول المصرح به إلى المعلومات.
- **تحضير:** التحليل وكتابة المسودات دون إرسال أو ترحيل.
- **تنفيذ محدود:** إجراءات منخفضة المخاطر ضمن قوائم وسقوف محددة.
- **تنفيذ بموافقة:** إرسال خارجي، ترحيل مستندات، تحديث بيانات مهمة وفق السياسة.
- **عمليات حساسة:** تحويل الأموال والحذف غير القابل للاسترجاع والقرارات القانونية والمالية عالية الأثر تتطلب قيودًا وموافقة صريحة قابلة للتدقيق، ولا يجوز تجاوزها.

تُحفظ الأسرار في مخزن آمن خارج المستودع. يشمل التنفيذ تأكيدات منع التكرار، وسجل تدقيق، وتوقفًا/إلغاءً آمنًا حيث ينطبق.

## 7. الإصدار الأول (MVP)

**ثلاث نتائج قابلة للإثبات:**
1. حفظ حقيقة أو إجراء معتمد واسترجاعه وتعديله وحذفه عبر جلسات.
2. اتصال **قراءة فقط** ببيانات محددة في أَوْج مع احترام الحدود.
3. إكمال **مسودة** فاتورة أو مطابقة كشف مع مصادر وتدقيق وموافقة بشرية قبل الترحيل أو الإرسال.

**مقاييس المتابعة:** نسبة النجاح، الدقة، التدخل البشري، الأخطاء المتكررة، زمن التنفيذ، التكلفة، جودة الاسترجاع، الالتزام بالصلاحيات. تُحدد الأهداف الرقمية بعد قياس مرجعي.
