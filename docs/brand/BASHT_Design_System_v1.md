# باشت | BASHT — Design System v1.0

> الحالة: الهوية البصرية من الحزمة الرسمية؛ مواصفات واجهة المستخدم أدناه **مقترحة** وتحتاج اعتمادًا قبل التطوير.

## 1. المبادئ

- مساعد تنفيذي عربي أولًا؛ وضوح النتيجة أهم من المؤثرات.
- Mobile-first للآيفون، وواجهة RTL مع دعم LTR.
- اعرض ما تم فعله فعلًا، وما ينتظر الموافقة، وما فشل، دون إيحاء زائف بالإنجاز.
- تجنّب الأزرار المتعددة للمهمة نفسها، وقلل خطوات المستخدم.
- أفعال الكتابة والحذف والإرسال والعمليات المالية تستلزم موافقة صريحة، مع عرض معاينة وتفاصيل الأثر.

## 2. الهوية المعتمدة (من الحزم المرفقة)

- الاسم: باشت | BASHT.
- الوصف: وكيل ذكاء اصطناعي.
- الرمز: روبوت يرتدي الدسمال اليمني والجنبية، مع نقطة الباء السفلية المنفصلة. يمنع دمج النقطة أو إسقاطها.
- لوحة الألوان:
  - `--brand-primary: #4C1D95` بنفسجي عميق.
  - `--brand-secondary: #7C3AED` بنفسجي حيوي.
  - `--brand-cyan: #06B6D4` سماوي رقمي.
  - `--brand-gold: #D4A017` ذهبي الجنبية.
  - `--brand-crimson: #D91B38` أحمر الدسمال (من حزمة Identity).
  - `--brand-surface: #EEF2FF` لافندر فاتح.
- الخط: IBM Plex Sans Arabic للنصوص العربية؛ IBM Plex Mono للأكواد والأرقام التقنية.
- الشعار هو أصل صورة مستقل؛ لا يعاد تركيب كلمة «باشت» بخط عادي بدل الرسم الرسمي.
- استخدم الرمز المبسط للأحجام الصغيرة؛ حد أدنى 16px، مع ترك مساحة أمان مناسبة.

### تنبيه اختلاف نسخ الحزم
الحزمتان الرسميتان المرفقتان تختلفان في بعض المقاسات والمعالجة اللونية لأيقونات التطبيق. حدّد المصدر النهائي عند التنفيذ بعد مراجعة النسخ مع المالك. حزمة Brand Identity تحتوي 15 PNG، بينما Identity FINAL تحتوي إضافة `bsht-mark-flat.png`.

## 5. Layout and Motion

- شبكة مسافات 4px؛ القياسات: 4/8/12/16/24/32/48px.
- Padding للبطاقات: 16–20px؛ للمحتوى الداخلي على الجوال: 16px.
- ارتفاع هدف اللمس: 44px على الأقل، والأزرار الأساسية 48–52px.
- زوايا الحقول 12px؛ البطاقات 16px؛ الحوارات 24px.
- Motion مدته 150–250ms للتفاعلات، 250–350ms للانتقالات الكبيرة، مع `prefers-reduced-motion`.
- ضع شريط المحادثة أسفل الشاشة مع مراعاة iOS safe area ولوحة المفاتيح.

## 6. Components

1. App shell: عنوان باشت، حالة الاتصال، قائمة المهام، إعدادات سهلة الوصول.
2. Conversation: رسائل المستخدم والوكيل، بث كتابة، مرفقات، نسخ، إعادة محاولة، ملخص سياق.
3. Composer: نص، ميكروفون، مرفقات، زر إرسال واضح؛ حالة التسجيل، إلغاء، مراجعة.
4. Voice session: Listening / Thinking / Speaking / Muted / Disconnected؛ زر إنهاء بارز وإمكانية المقاطعة.
5. Task card: نوع المهمة، المصدر، النطاق، حالة التنفيذ، الأثر، الوقت، النتائج والتحقق.
6. Approval dialog: الإجراء المطلوب، الجهة/الحساب، البيانات قبل/بعد، خيار تأكيد صريح وإلغاء.
7. Status: `draft`, `awaiting_approval`, `running`, `verified`, `failed`, `cancelled`؛ أيقونة ونص بجانب اللون.
8. File preview: اسم، نوع، معاينة، التحميل عند الإمكان، وتفسير أخطاء الملف.
9. Notifications: رسائل قصيرة، قابلة للتصفية، ولا تدعي النجاح قبل التأكيد من النظام الخارجي.
10. Integrations: GitHub, Railway, WhatsApp, ERP كاتصالات اختيارية واضحة الصلاحيات.

## 7. صفحات المنتج

- الرئيسية / المحادثة.
- المحادثة الصوتية المباشرة.
- المهام وسجل التنفيذ.
- الموافقات المعلقة.
- الملفات والذاكرة التشغيلية.
- التكاملات والصلاحيات.
- الإعدادات والمظهر واللغة.

## 8. الأمان وتجربة الوكيل

- لا تنفذ إجراء حساسًا غير قابل للتراجع دون اعتماد منفصل.
- اعرض للمستخدم مصدر البيانات، وحدود صلاحية الأداة، وحالة التحقق.
- لا تظهر الأسرار أو مفاتيح API في النصوص أو السجلات أو الإشعارات.
- أي طلب كتابة على منصة خارجية يوضح النطاق ويحتاج الموافقة المطلوبة.
- ميّز بين `تم التخطيط` و`جار التنفيذ` و`تم التحقق` و`فشل`.

## 9. تنفيذ مقترح

- Design Tokens في CSS variables أو JSON لتطبيقات الويب.
- React/Next.js + TypeScript + Tailwind + مكتبة مكونات داعمة لـ RTL إن كان المنتج ويب.
- اعتمد عناصر SVG أصلية للهوية عند توفرها؛ الصور PNG الحالية ليست دليلًا على وجود ملفات vector أصلية كاملة.
- وثّق حالات المكونات في Storybook أو واجهة توثيق مماثلة.
- اختبر في Safari على iPhone مع لوحة المفاتيح، Safe Areas، والإنجليزية/العربية والوضع الداكن.

## 10. معيار الاعتماد

يُعتمد النظام بعد: فحص الألوان والتباين، مطابقة الأصول، اختبار الاستخدام على الآيفون، اختبار RTL/LTR، حالات انقطاع الشبكة، وحوارات الموافقة، والتحقق من أن التصميم لا يوحي بتنفيذ عمليات لم تقع.
