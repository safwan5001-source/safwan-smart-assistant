# باشت | BASHT — تطبيق الهوية وتجربة الواجهة

> مرجع الهوية: [`BASHT_Design_System_v1.md`](BASHT_Design_System_v1.md). هذا الملف يوثّق ما نُفّذ في التطبيق، ولماذا، وما بقي معلّقًا.

## 1. مصدر الشعار (لا رسم جديد)

| البند | القرار |
|---|---|
| المصدر الوحيد | `docs/brand/source/basht-logo-primary-official.png` — الشعار الكامل الذي أرسله المالك (جنبية فضية/بنفسجية، اعتُمدت كنسخة نهائية بقرار المالك). |
| حزم Brand Identity / Identity FINAL | **غير متاحة** في بيئة التطوير. لم يُستخدم أي شعار بديل أو مولّد. عند توفرها تُستبدل الأصول بإعادة تشغيل المولّد على الملف الرسمي. |
| العمليات المسموحة | إزالة الخلفية البيضاء المسطحة، قص، تغيير حجم، نسخة أحادية بيضاء للكلمة (نفس معاملة `bsht-mono-white`) مأخوذة من **حبر الحروف البنفسجي فقط**، ووضع الرمز كما هو على بلاطة للأيقونات. |
| المحفوظ | الجنبية، الدسمال اليمني، **نقطة الباء السفلية المنفصلة** داخل قصّ الكلمة. |
| التوليد | `python3 apps/web/scripts/generate-brand-assets.py` (حتمي، يحتاج Pillow/numpy/scipy). |

### ضمانات الدقة (يفشل المولّد إن خُرقت)

- **مطابقة المصدر:** كل بكسل معتم في القصّ يساوي الملف الرسمي حرفيًا؛ لا إعادة تلوين ولا رسم.
- **نقطة الباء المنفصلة:** تُعدّ أشكال الكلمة (8 أشكال: «با»، «شت»، نقطة الباء، نقطتا التاء، ونقاط الشين الثلاث) عند المقاس الأصلي وعند 144px وفي بطاقة المشاركة (110px). أي اندماج يوقف التوليد.
- **سبب استخراج النسخة البيضاء من الحبر:** في الرسم الأصلي تحيط بالحروف والنقطة حافة فاتحة لامعة تتلامس عند الباء. تبييض هذه الحافة كان يدمج النقطة بالحرف (خلل في النسخة الأولى، صُحّح). النسخة البيضاء الآن تُبنى من الحبر البنفسجي مع ملء لمعة النقطة وحذف شظايا الحافة.
- **الأيقونات الصغيرة (16/32/48):** تصغير Lanczos ثم تحسين حدة خفيف على اللون فقط (الشفافية لا تُمسّ). لا يوجد «رمز مبسّط» بنسخة الجنبية الفضية في المصدر المتاح، فيُستخدم الرمز الكامل.
- **الشفافية:** علامات وكلمات الواجهة WebP بقناة ألفا (الكلمات و`mark-sm` بلا فقد)؛ أيقونات الشاشة الرئيسية PNG معتمة لأن iOS يملأ الشفافية بالأسود. اختبارات `tests/brand.test.ts` تتحقق من ذلك من رؤوس الملفات.

ملاحظة تقنية: خلفية الملف مسطحة تمامًا (انحراف ≤ 1 عن ‎#FEFEFE) بينما أبيض الدسمال مُلوَّن (≥ 4)، لذلك تُزال الخلفية بعتبة صارمة مع قطع الجسور الرقيقة كي لا يُمسح الدسمال الملامس للحافة.

## 2. نقاط الضعف التي عولجت (UX audit)

| قبل | بعد |
|---|---|
| الرئيسية لوحة إحصاءات عامة؛ لا تجيب «ماذا يفعل الوكيل الآن؟» | **مركز قيادة**: حالة باشت الحية، حقل «اطلب من باشت»، الخطوة التالية المقترحة، بانتظارك، ملخص اليوم، التالي، الاتصالات، ما أُنجز |
| لا شخصية للوكيل؛ «المساعد» نص عام | **AgentOrb**: وجه باشت + حلقة حالة؛ تتحرك فقط أثناء عمل حقيقي |
| حالات الوكيل غير ظاهرة خارج فقاعة البث | مخزن `agent-activity` في الذاكرة يغذي الشريط الجانبي، الرئيسية، رأس المحادثة وزر التبويب |
| المحادثة في تبويب جانبي | باشت في **منتصف** الشريط السفلي (تحت الإبهام) |
| شاشة الصوت مجرد زرين | **جلسة صوتية**: هالة استماع، أشرطة، حالات صريحة، «راجع وأرسل لباشت»، مؤثرات اختيارية |
| حالة فارغة نصية | رمز باشت + اقتراحات بنقرة (تملأ الحقل فقط ولا ترسل) |
| شارات حالة باللون غالبًا | `StatusPill` (§6.7): أيقونة + نص + لون دائمًا |
| خط النظام | IBM Plex Sans Arabic / Plex Mono مستضافة ذاتيًا (تعمل دون اتصال) |
| الداكن عكس ألوان | داكن مستقل: طبقات بنفسجية، توهج سماوي، حواف مضيئة داخلية |

## 3. حالات الوكيل — مصدر كل حالة

| الحالة | المصدر الحقيقي |
|---|---|
| يتحقق / غير متصل | `/api/health` |
| وضع الملاحظات / جاهز | `assistant` في رد الصحة |
| يفكّر | أُرسل الطلب إلى Claude ولم يصل أول جزء |
| يكتب الرد | وصول أجزاء البث |
| **اكتمل الرد** / تعذّر الرد / أُوقف | نتيجة رد Claude — **رد نصي فقط، لا يعني تنفيذ أي إجراء** |
| **نُفّذت المهمة** / تعذّر التنفيذ | أمر محلي نُفّذ فعلًا (‎/مهمة، تذكير) أو بطاقة متصفح انتقلت فعليًا من «بدأت» إلى نتيجة؛ إعادة فتح بطاقة قديمة لا تُحتسب، والإدخال غير الصالح لا يُحتسب |

نتائج الرد والتنفيذ تظهر 4 ثوانٍ ثم تعود الحالة للاتصال.

**الصوت منفصل عن الوكيل:** شاشة الصوت تعرض حالة الميكروفون فقط (`VoiceOrb` بـ `data-voice`: جاهز / يُسجَّل / غير مدعوم / خطأ) ولا تستخدم أي حالة للوكيل؛ التسجيل لا يغيّر حالة باشت في الشريط أو الرئيسية.

**غير مفعّل عمدًا:** «يبحث» و«ينتظر الموافقة» كحالة عامة للوكيل — لا يوجد بعد مصدر حقيقي لهما خارج بطاقات المتصفح داخل المحادثة (التي تعرض موافقتها بنفسها). قسم «بانتظارك» يعرض فقط ما ينتظر إجراءً فعلًا: تذكيرات وصلت، مهام متأخرة، إشعارات غير مقروءة.

## 4. الرموز (Tokens) والتباين

الألوان الرسمية ثابتة في `--brand-*`. أدوار الواجهة في `app/globals.css`. نتائج فحص WCAG (نص/خلفية):

| الزوج | فاتح | داكن |
|---|---|---|
| النص / الخلفية | 16.9 | 18.1 |
| الثانوي / السطح | 6.5 | 9.0 |
| التمييز / السطح | 7.1 | 9.7 |
| نجاح / خلفيته | 5.5 | 8.6 |
| تحذير / خلفيته | 4.5 | 8.6 |
| خطر / خلفيته | 5.6 | 5.8 |
| أبيض على تدرج الأزرار (أفتح نقطة) | 5.7 | 5.7 |

السماوي والذهبي لا يُستخدمان نصًا صغيرًا على الأبيض؛ نسختا النص `--ai-ink` و`--gold-ink` تحققان AA.

## 5. التخطيط

شبكة الرئيسية: بطاقة «التالي في جدولك» تمتد عمودين (`.span-lg-2`) **فقط** داخل شبكة الأعمدة الثلاثة (≥ 1000px). على الجوال والآيباد عمود واحد كامل العرض (يتحقق منه اختبار وحدة وفحص e2e على iPhone).

«تذكيرات اليوم» = التذكيرات النشطة أو المنتظرة إجراءً التي يقع موعدها بين منتصف ليل اليوم ومنتصف الليل التالي بتوقيت الجهاز.

## 6. الحركة والأداء

- 150–250ms للتفاعلات، 320ms للانتقالات؛ كل الحركة تُلغى مع `prefers-reduced-motion`.
- لا مكتبات جديدة. الخطوط مقسّمة بـ `unicode-range` (تُحمَّل العربية فقط حين تلزم). زيادة JS لكل صفحة 1–8 KB.
- شاشة الإطلاق داخل التطبيق CSS فقط وتعمل في وضع التثبيت (standalone) فقط.

## 7. التوافق والبيانات

- **لم تتغير** أي مفاتيح تخزين (`safwan-*`) ولا قاعدة IndexedDB (`safwan-files-v1`)؛ اختبار `tests/brand.test.ts` يثبت ذلك.
- `id` و`start_url` في الـ manifest كما هما، فيتحدث التطبيق المثبّت ولا يظهر كتطبيق ثانٍ.
- **iOS يثبّت اسم وأيقونة التطبيق لحظة الإضافة للشاشة الرئيسية**: النسخ المثبتة سابقًا تبقى «صفوان» حتى تُحذف وتُضاف من جديد (موضح في الإعدادات).
- مفتاح جديد واحد فقط: `safwan-voice-fx` (تفضيل المؤثرات الصوتية، افتراضيًا مطفأ).

## 8. معلّق

- استبدال الأصول بحزم Brand Identity / Identity FINAL الأصلية (SVG إن وُجد) عند توفرها.
- واجهة إنجليزية/LTR: التطبيق عربي فقط حاليًا؛ كل التخطيط بخصائص منطقية جاهز للعكس.
- `metadataBase` لصور المشاركة: يُضبط تلقائيًا على Vercel؛ على Railway يلزم أصل عام إن أُريدت معاينات الروابط.
