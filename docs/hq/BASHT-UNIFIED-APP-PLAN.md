# خطة التطبيق الموحّد: التطبيق هو باشت

> **الحالة:** U1 (#56) وA1 (#57) منشورتان في الإنتاج، وFace ID جاهز وينتظر النطاق الدائم. M (التحكم بالنماذج) منفَّذة في هذا الفرع مع جسر المحرك (openclaw-railway-template #49)، وتنتظر المراجعة قبل النشر. الصوت يليها.
>
> **المبادئ:**
> - لا أنظمة موازية، ولا تكرار للواجهات.
> - لا خيارات وهمية.
> - تبقى الهوية والوظائف والبيانات والصلاحيات كما هي.

## 1. U1: محادثة واحدة (منفَّذة)

**المسار والمحرّك**

| البند | ما تحقّق |
|---|---|
| المسار | تبويب «باشت» ← `/chat`، وهي المحادثة الفعلية نفسها. أُزيلت بطاقة «تحدّث مع باشت الفعلي» والصفحة المنفصلة. `/chat/basht` و`/calls` تُعاد توجيهًا إليها |
| العقل | باشت (المحرك، جلسة `app:owner`) هو الافتراضي. Claude المباشر (CHAT-AI-1) محفوظ، ويخدم المحادثة نفسها فقط إذا لم يُضبط محرك على الخادم. لا يظهر كمحادثة ثانية |

**ما يُعرض داخل المحادثة**

| البند | ما تحقّق |
|---|---|
| خط زمني واحد | رسائل المحرك (على الخادم ومشتركة بين الأجهزة) تُدمج حسب الوقت مع أحداث هذا الجهاز. أحداث الجهاز هي الأوامر السريعة والتذكيرات وبطاقات المتصفح والمرفقات، وتُحفظ في خيط محلي واحد (`main`) |
| الأوامر السريعة | `/مهمة`، التذكير، `/متصفح`، أوامر الجلسة التفاعلية. تُنفَّذ محليًا ولا تُرسل لأي نموذج أبدًا (اختبار F4) |
| الانقطاع | لا تحوّل تلقائي إلى الملاحظات. عند الانقطاع أو قفل الجلسة يظهر شريط واضح، ولا تُسجَّل الرسالة كمرسلة، ويبقى النص في مربع الكتابة. يُمسح النص فقط بعد قبول باشت للدورة |
| الأرشيف | المحادثات المحلية القديمة تُعرض كما هي (للقراءة، مع النسخ والتعديل والحذف والأرشفة والبحث) |
| المحادثات الأخرى | واتساب والجلسة الرئيسية للقراءة فقط |
| الصوت | الإملاء في مربع الكتابة، والجلسة الصوتية لوحة داخل المحادثة (`?voice=1`) ينتقل نصها إلى مربع الكتابة نفسه |
| الحالة | مؤشر الحالة (Orb) يتبع المحرك. «جاهز» تعني أن باشت متصل، و«غير متصل» تعني أن الرسائل لن تُرسل |

**الأمان:** بلا تغيير. الجسر نفسه، وبوابة المالك نفسها، وعزل الجلسات نفسه، والقراءة محصورة في محادثات المالك.

## 2. A1: مصادقة موحدة مع Face ID (منفَّذة، دمج U2 وU4 في بناء واحد)

**الفكرة:** جلسة مالك واحدة للتطبيق كله، ولها طريقتا دخول: رمز المالك أو Face ID. الطريقتان تُنشئان **الجلسة نفسها** من نواة الجلسات الموجودة، فلا يوجد نظام جلسات ثانٍ.

```
المتصفح ──▶ BFF /api/auth/* ──HMAC──▶ API /internal/v1/auth/* ──▶ PostgreSQL (sessions + passkeys تحت RLS)
                  │
                  └─ كوكي safwan_session (HttpOnly · SameSite=Strict · Secure · Path=/) يفتح /api/basht و/api/browser و/api/assistant
```

### ما بُني
| الطبقة | التفاصيل |
|---|---|
| **قاعدة البيانات** (`0005_owner_auth.sql`، إضافي ومتوافق مع الكود السابق) | جدول `passkeys` تحت RLS. دوال SECURITY DEFINER بمسار بحث ثابت `pg_catalog, pg_temp`: `auth_ensure_owner` (تُنشئ حساب «المالك» مرة واحدة فقط إن لم يوجد أي حساب)، و`auth_passkey_lookup`، و`auth_passkey_used` (العدّاد يتقدم فقط). |
| **API** (`app/auth/owner.py`) | الدخول بالرمز مع مقارنة ثابتة الزمن وحدّ 10 محاولات فاشلة في 15 دقيقة. WebAuthn عبر `py_webauthn` (بلا تشفير يدوي)، بشرط residentKey وuserVerification. التحدي مختوم بـ HMAC ولمدة 5 دقائق، ويُستخدم مرة واحدة عبر مخزن منع الإعادة الحالي. سجل تدقيق لكل دخول. |
| **مدة الجلسة** | 12 ساعة افتراضيًا (كانت 7 أيام)، و30 يومًا عند اختيار «تذكّر هذا الجهاز». الانتهاء بساعة قاعدة البيانات. |
| **BFF** (`server/owner-session.ts`، `server/owner-auth.ts`) | مساعد واحد `doorAccess` تستخدمه الأبواب الثلاثة. الطلب بلا كوكي جلسة لا يصل إلى الـ API إطلاقًا. التحقق مخزَّن 15 ثانية. كل كتابة من نفس الأصل فقط. تحدي WebAuthn في كوكي HttpOnly على `/api/auth` لمدة 5 دقائق، ويُحذف بعد التحقق، ناجحًا كان أو فاشلًا. |
| **الواجهة** | مكوّن دخول واحد `OwnerSignIn` (Face ID، ثم الرمز، و«تذكّر هذا الجهاز 30 يومًا») يظهر في المحادثة. بطاقة «الدخول والأمان» في الإعدادات تعرض حالة الدخول، وتتيح إضافة Face ID وإدارة الأجهزة وإزالتها، والخروج من هذا الجهاز أو من كل الأجهزة. |
| **الانتقال** | ما دام `OWNER_AUTH` غير مفعّل، تعمل الرموز القديمة كما هي حرفيًا. بعد التفعيل، يدخل نموذج الفتح القديم في أي باب إلى الجلسة الموحدة نفسها، فيكفي رمز واحد. |

**قاعدة على الاتصال الداخلي:** الـ BFF يعتبر 401/403 رفضًا للتوقيع، و429 و5xx تعذّرًا في الخدمة. لذلك يردّ الـ API على رفض المالك (رمز خاطئ، جلسة منتهية، تجاوز الحد) بـ 400 مع رمز، والـ BFF يعيد ترجمته إلى 401/403/429 للمتصفح. بهذا لا يختلط «رمز خاطئ» بـ«الخادم غير متاح».

### المتغيرات
| المتغير | الخدمة | الوظيفة |
|---|---|---|
| `OWNER_ACCESS_CODE` | API فقط (≥ 32 حرفًا، سري) | يفعّل الدخول الموحد. بدونه ترد كل المسارات 503. |
| `OWNER_AUTH=on` | الويب (مفتاح تشغيل، ليس سرًا) | يجعل الأبواب تقبل الجلسة الموحدة ويُظهر واجهتها. |
| `BASHT_PUBLIC_ORIGIN` | API (مثل `https://app.example.com`) | النطاق الدائم الذي يرتبط به مفتاح Face ID. بدونه يبقى Face ID معطّلًا ويعمل الدخول بالرمز. |

### خطوات النشر (بعد الاعتماد)
1. دمج الطلب، ثم نشر API والويب. الكود الجديد خامل ما دام المفتاحان غير مضبوطين.
2. إعادة نشر خدمة `safwan-db-job` (`python -m app.db.migrate`) لتطبيق الترحيل 0005.
3. ضبط `OWNER_ACCESS_CODE` على الـ API، ثم `OWNER_AUTH=on` على الويب. بعدها التحقق: دخول بالرمز، وفتح الأبواب الثلاثة، والخروج.
4. بعد ربط النطاق الدائم بخدمة الويب على Railway: ضبط `BASHT_PUBLIC_ORIGIN`، ثم تسجيل Face ID من الإعدادات على الآيفون.
5. بعد أسبوع من الاستقرار: حذف `AI_CHAT_ACCESS_CODE` و`BROWSER_CHAT_ACCESS_CODE` و`BASHT_CHAT_ACCESS_CODE`.

**التراجع:** حذف `OWNER_AUTH` من الويب يعيد السلوك السابق فورًا. الترحيل إضافي ولا يحتاج تراجعًا.

### التحقق
- **API مع PostgreSQL:** 691 اختبارًا ناجحًا، منها 13 لهذا الجزء، مع مصادِق برمجي حقيقي (ES256) يختبر: إعادة استخدام التحدي، والتحدي من نوع خاطئ، وأصلًا مزيّفًا، ومفتاحًا غير مسجَّل، وتراجع العدّاد، وحذف المفتاح.
- **الويب:** 571 اختبارًا ناجحًا، منها 17 للـ BFF، والمحاكاة فيها تطابق تصنيف `callBackend` الحقيقي.
- **مختبر السلسلة الكاملة** (متصفح ← BFF ← API ← PostgreSQL، ومصادِق افتراضي عبر CDP): 20/20. يشمل: الدخول بالرمز، وفتح الأبواب الثلاثة بجلسة واحدة، وتسجيل Face ID، والخروج، والدخول بـ Face ID مع تذكّر 30 يومًا، ورفض كوكي مزوّر، ورفض طلب من موقع آخر، وأن «الخروج من كل الأجهزة» ينهي جلسة جهاز آخر، وأن نموذج الفتح القديم يدخل إلى الجلسة الموحدة.

### 2.1 بوابة الدخول (تصحيح تجربة الدخول)
الدخول بوابة التطبيق كله، لا نموذجًا داخل المحادثة. تبني على جلسة A1 نفسها دون نظام موازٍ.

| الجزء | السلوك |
|---|---|
| **الخادم** (`middleware.ts`، تشغيل Node) | مع `OWNER_AUTH=on` لا تُرسَل أي صفحة دون جلسة مالك صالحة: تحويل 307 إلى `/login?next=<المسار والاستعلام>`. صفحة الدخول تحوّل إلى `next` مباشرة إن كانت الجلسة قائمة. إذا تعذّر الوصول إلى الـ API تُعرض صفحة الدخول مع رسالة واضحة، ولا يُفتح التطبيق (الإغلاق عند الفشل). مسارات `/api/*` تحمي نفسها وتردّ 401، والملفات الثابتة عامة. |
| **صفحة الدخول** `/login` | صفحة مستقلة بهوية باشت (الشعار والاسم والوصف)، بلا شريط تنقل ولا أي بيانات من التطبيق. تدعم الوضعين الفاتح والداكن والجوال. الدخول برمز المالك مع «تذكّر هذا الجهاز 30 يومًا». Face ID مخفي حتى يُربط النطاق الدائم. |
| **الوجهة** | تُقبل `next` فقط إن كانت مسارًا داخل التطبيق نفسه؛ أي رابط خارجي أو `/login` أو `/api` يُستبدل بالرئيسية. |
| **انتهاء الجلسة أثناء الاستخدام** | مراقب واحد (عند العودة إلى التطبيق، وعند التركيز، وكل دقيقة)، وكل باب يكتشف انتهاء الجلسة يحوّل فورًا إلى `/login?next=<المكان الحالي>&reason=expired`، ثم يعود إلى المكان نفسه بعد الدخول. لا يُعاد التوجيه عند خطأ شبكة. |
| **الجلسات والأجهزة** | في «الدخول والأمان»: الجلسات النشطة باسم الجهاز (مثل «آيفون · Safari»)، مع تمييز هذا الجهاز وآخر نشاط ومدة الجلسة وموعد انتهائها. يمكن إنهاء أي جلسة، والخروج من هذا الجهاز أو من كل الأجهزة، ثم يُعاد المستخدم إلى صفحة الدخول. |
| **قاعدة البيانات** | الترحيل 0006 إضافي: عمود `device_label` فقط، ولا تغيير على الصلاحيات أو السياسات. النشاط يُسجَّل مرة كل 5 دقائق على الأكثر. |

**الإيقاف:** حذف `OWNER_AUTH` من الويب يعيد السلوك السابق فورًا.

**التحقق:** API ‏694 اختبارًا ناجحًا، والويب 584، ومختبر السلسلة الكاملة 28/28. يشمل المختبر:
- رفض الخادم كل الصفحات الخاصة دون جلسة؛
- العودة إلى الرابط العميق بعد الدخول؛
- كوكي «تذكّر» لمدة 30 يومًا؛
- قائمة الجلسات بأسماء الأجهزة؛
- إنهاء جلسة جهاز آخر وعودته إلى الدخول ثم إلى مكانه؛
- الوضع الداكن؛
- تجاهل `next` الخارجي؛
- الخروج من هذا الجهاز ومن كل الأجهزة.

## 3. M: التحكم بالنماذج داخل واجهة باشت

يعتمد هذا القسم على فحص OpenClaw 2026.11.10 (الوثائق والكود). لا يُعرض إلا ما يدعمه المحرك فعلًا.

### ما يدعمه المحرك وطريقة الوصول إليه

| الحاجة | المتاح في المحرك | طريق الجسر |
|---|---|---|
| قائمة النماذج المتاحة والمصرَّح بها | `models.list`، ولكل نموذج: المزوّد، والتوفر، وسبب عدم التوفر (مصادقة، أو تبريد حتى وقت محدد…)، ونافذة السياق، و`reasoning`، و`thinkingLevels`، و`supportsFastMode`، والمدخلات (نص، صورة…)، و`recommended` | عبر `openclaw gateway call` (WebSocket فقط)، مع تخزين مؤقت. الجسر يشغّل CLI أصلًا |
| النموذج النشط للجلسة | أداة `session_status`: `model`، `modelProvider`، `modelOverride` | `/tools/invoke` |
| تبديل النموذج للجلسة (دائم) | أداة `sessions` `patch {model}`، و`"default"` يعيد الافتراضي | `/tools/invoke` مع تحقق مسبق من القائمة |
| مستوى التفكير | `sessions` `patch {thinkingLevel}`. القيم من `off` إلى `max`، ويُقبل فقط ما يعلنه النموذج | `/tools/invoke` |
| وضع السرعة (Fast) | `sessions.patch {fastMode}`، ويُعرض فقط إذا أعلن النموذج `supportsFastMode` | CLI فقط |
| النموذج الذي نفّذ الرد فعليًا | كل رد في السجل يحمل `provider` و`model` | تمرير الحقلين في `/history` (لا يُمرَّران اليوم) |
| الانتقال إلى نموذج احتياطي | يظهر في `session_status` (سطر «Fallback»)، مع النموذج المختار والفعلي والسبب | يُعرض كما هو |
| حفظ السياق والذاكرة عند التبديل | نعم: الجلسة والسجل نفسهما. التبديل قد يفقد ذاكرة التخزين المؤقت ويغيّر نافذة السياق، ويُنبَّه المستخدم لذلك | — |
| الاستخدام | الرموز (`contextTokens`/`totalTokens`) والتكلفة في نص الحالة | `/tools/invoke` |

### ما لن يُعرض لأنه غير موجود في المحرك
- **«وضع تلقائي» لاختيار النموذج:** لا يوجد في OpenClaw. يوجد فقط ترتيب النموذج الأساسي ثم الاحتياطي. يظهر «تلقائي» فقط إن كان نموذج مزوّد مثل `openrouter/auto` ضمن القائمة فعلًا.
- **زمن الاستجابة لكل نموذج وحدود المعدّل:** تتطلب إضافة غير مثبتة. البديل الصادق: زمن آخر رد كما قاسه الجسر نفسه.
- **الحصص والتكلفة التفصيلية:** متاحة عبر WebSocket فقط، فتُؤجَّل.
- **`/v1/models`:** لا يُستخدم، لأنه يعرض وكلاء لا نماذج.
- **ترويسة `x-openclaw-model`:** لا تُستخدم كاختيار محفوظ.

### الواجهة (داخل المحادثة نفسها)
- **رأس المحادثة:** شارة بالنموذج النشط والمزوّد. يفتح الضغط عليها لوحة تضم:
  - قائمة النماذج المتاحة. غير المتاح يظهر معطّلًا مع سببه، أو يُخفى.
  - مستوى التفكير، بقيم النموذج المختار فقط.
  - وضع السرعة إن كان مدعومًا.
  - القدرات: سياق، صور، أدوات.
  - استخدام الجلسة.
- **تحت كل رد:** النموذج الذي نفّذه فعليًا، مع علامة واضحة عند الانتقال إلى نموذج احتياطي.

### ما بُني (M)
| الطبقة | التفاصيل |
|---|---|
| **المحرك** (#49) | `GET /app/v1/models` و`GET /app/v1/model`، و`POST /app/v1/model\|thinking\|fast`. الكتابة على جلسة التطبيق فقط، وبقيم من قائمة المحرك نفسها. لا تعديل على الإعدادات ولا على النماذج الافتراضية والاحتياطية. |
| **API** | صفوف بشكل ثابت (لا مفاتيح ولا عناوين ولا كائنات خام). تحقق قبل الوصول إلى المحرك، وتدقيق لكل تغيير. رموز الرفض المحددة تُمرَّر من قائمة ثابتة. المحرك الذي لا يدعم التحكم يُقرأ «غير متاح» فتختفي اللوحة، ولا يُقرأ «انقطاعًا». |
| **السجل** | كل رد يحمل النموذج الذي كتبه. إشعار OpenClaw «Model switched from…» لا يُعرض كرد إنجليزي من باشت؛ يُضم سجله إلى الرد الذي تلاه. |
| **الواجهة** | الرأس: «جاهز · النموذج · مستوى التفكير · سريع». لوحة «النموذج والقدرات» فيها: النموذج النشط ومصدره (افتراضي أو مثبّت)، وآخر رد وزمنه المقاس، والانتقال الاحتياطي وسببه، واستخدام السياق، ومستويات التفكير الخاصة بالنموذج، ووضع السرعة إن كان مدعومًا، والنماذج المسموح بها مجمّعة حسب المزوّد مع قدراتها وتوفرها. تحت كل رد: النموذج الذي كتبه، مع علامة واضحة عند الانتقال إلى نموذج احتياطي. |

**صدق العرض:** الواجهة لا تفترض نجاح أي تغيير. بعد كل تغيير تعيد قراءة الحالة من المحرك حتى يظهر فيها (المحرك يطبّق التغيير بعد لحظة من تأكيده)، وتعرض «جارٍ التطبيق على باشت…» أثناء ذلك.

### التحقق
- **API:** 705 اختبارات ناجحة. **الويب:** 585 اختبارًا ناجحًا.
- **مختبر السلسلة الكاملة** (آيفون ← BFF ← API ← الجسر عبر HTTPS ← بوابة OpenClaw 2026.11.10 حقيقية ← مزوّد تجريبي): **24/24**. يشمل:
  - القائمة هي قائمة الوكيل المسموح بها فقط، والنموذج الخارج عنها غائب ومرفوض.
  - مستوى التفكير `low` وصل إلى المزوّد بقيمة `reasoning_effort: "low"`.
  - التبديل إلى grok-3 مع الوضع السريع: وصل المزوّد طلب `grok-3-fast`.
  - بقاء سياق المحادثة بعد التبديل.
  - رفض الوضع السريع على نموذج لا يدعمه.
  - العودة إلى النموذج الافتراضي.
  - فشل حقيقي في النموذج الأساسي: أجاب الاحتياطي echo2، وعُلِّم الرد بذلك مع السبب، وأظهرت اللوحة الانتقال.

### ملاحظات للإنتاج
- يجب أن تسمح سياسة أدوات الإنتاج بأداة `sessions` عبر `/tools/invoke`. يُتحقق من ذلك فور النشر.
- كل تغيير يستغرق 3–5 ثوانٍ، لأن الجسر يشغّل `openclaw gateway call` لكل طلب. يمكن تحسين ذلك لاحقًا بعميل WebSocket دائم، دون تغيير الواجهة.
