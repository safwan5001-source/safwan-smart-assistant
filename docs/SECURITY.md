| M4 الإشعارات | تسجيل جهاز جديد يتطلب جلسة المالك عند تفعيل `OWNER_AUTH`. |
| L1 عنوان العميل | مساعد واحد `server/client-ip.ts` لكل الحدود: `X-Real-IP` الذي تضبطه حافة Railway، ثم آخر قيمة في `X-Forwarded-For` فقط. |
| L2 زمن الإلغاء | التخزين المؤقت للجلسة 5 ثوانٍ (كان 15). الخروج وإنهاء أي جلسة والخروج من الكل تمسح ذاكرة هذا المثيل فورًا. يبقى حتى 5 ثوانٍ على مثيلات أخرى إن وُجدت (اليوم مثيل واحد). |
| L3 | CSP وHSTS (أعلاه). `script-src` يسمح بـ `'unsafe-inline'` لأن Next يبث بياناته في سكربتات مضمّنة والصفحات ثابتة (nonce يجعل كل الصفحات ديناميكية). |
| L5 ربط مسارات باشت بالحساب | **لم يُنفَّذ**: التحقق في الـ API يحتاج مفتاح تشغيل إضافيًا، وإلا كسر مسار الرموز القديمة والتراجع الموثّق بحذف `OWNER_AUTH`. الـ BFF يبقى نقطة التفويض الوحيدة. |
| L8 بيانات الجهاز بعد الخروج | الخروج (هذا الجهاز، كل الأجهزة، أو إنهاء جلسة هذا الجهاز) يمسح المهام والمحادثات المحلية والسجل والتذكيرات والإشعارات وتفضيلاتها وحامل جهاز الإشعارات (بعد حذفه من الخادم) والملفات المحفوظة في المتصفح. يبقى المظهر والوضع المضغوط ونمط المهام وأصوات الواجهة. **لا يُمسح عند انتهاء الجلسة أو إنهائها من جهاز آخر**: لا يمكن تمييز ذلك عن الانتهاء الطبيعي بعد 12 ساعة، والمسح حينها يفقد المالك بيانات غير متزامنة. |
| L4 (المحرك) | توصية فقط: الشبكة الخاصة لـ `BASHT_CORE_URL` أو توقيع نداءات الجسر. انظر `docs/BASHT_APP_BRIDGE.md` في مستودع المحرك. |

**أثر النشر:** بعد النشر تنتهي كل الجلسات الحالية مرة واحدة (الكوكي الجديد موسوم، والبصمة المخزنة صارت مربوطة بالرمز). يكفي الدخول بالرمز من جديد. وتغيير `SERVICE_AUTH_SECRET` أو `OWNER_ACCESS_CODE` لاحقًا يُخرج كل الأجهزة كذلك.

## مخاطر متبقية (تحتاج قراراً/عملاً لاحقاً)
1. **لا مصادقة حقيقية**: أي نشر لمسارات API غير الصحية يتطلب أولاً حساباً (OIDC/جلسات) — حالياً مقفلة عمداً.
2. **بيانات المتصفح غير مشفّرة** (localStorage/IndexedDB) ولا نسخ احتياطي؛ حذف بيانات الموقع يفقدها. يوجد تصدير JSON للمهام والمحادثات فقط.
3. **سجل التدقيق في الذاكرة**: يضيع عند إعادة التشغيل؛ يلزم تخزين دائم (PostgreSQL) قبل أي تنفيذ حقيقي.
4. **لا قناة موافقات**: الأدوات الحساسة تُحجز ولا تُنفَّذ؛ تدفق الموافقة الخاص بكل عملية (مع منع التكرار) غير مبني.
5. حدود المعدّل في ذاكرة كل مثيل (لا مخزن مشترك)، وCSP تسمح بالسكربتات المضمّنة (`unsafe-inline`)؛ CSP بـ nonce تتطلب عرض كل الصفحات ديناميكيًا.
6. **الإملاء الصوتي** يعتمد على خدمة المتصفح/مزوّده وقد يرسل الصوت لخارج الجهاز.
7. (B1) تحويل `vercel.json` إلى BFF + Service Binding **لم يُثبت على Vercel بعد** — انظر `docs/B1-PREVIEW-CHECKLIST.md`.
8. (B1) قفل الاعتماديات: CI يستخدم `--frozen-lockfile` (pnpm) و`uv.lock` (Python).
9. (B1) **آليتا مصادقة منفصلتان تحت `/internal/*` بقرار معماري معتمد**: `/internal/v1/*` (BFF→API) بتوقيع HMAC وفق `SERVICE_AUTH_SECRET` مع نونس أحادي الاستعمال؛ و`/internal/browser/*` (تشخيص/قراءة المتصفح) بـ`Authorization: Bearer <BROWSER_SERVICE_TOKEN>` (≥ 32 حرفًا). لا يفتح أي اعتماد منهما الآخر، ولا يوجد إعفاء عام لأي بادئة. `tests/test_internal_auth_boundary.py` يفشل إن أُضيف مسار تحت `/internal` دون إدراجه صراحةً أو دون حارس. المسارَان `smoke`/`read` ما زالا ظاهرَين في `/openapi.json` (الافتراضي، كما على `main`)؛ الـAPI بلا نطاق عام. توحيد الآليتين وإخفاؤهما من المخطط **مهمة مستقلة**.
10. (B1) **Independent Security Review** (ليست Codex): `docs/INDEPENDENT-SECURITY-REVIEW.md` — النتائج وما أُصلح وما بقي. المتبقي الأهم: نطاق الحساب GUC قابل للضبط ممن ينفّذ SQL بدور التشغيل (IR-B1)، وثغرتا توافر في الإشعارات من `main` (IR-W2/W3)، وترقية Next.js (IR-W4).

11. (CHAT-BROWSER-1) **مسار ثالث موقَّع** `/internal/v1/browser/tasks*` (BFF→API بنفس HMAC) لمهمة المتصفح من المحادثة، مطفأ افتراضيًا (`BROWSER_CHAT_ENABLED`) وببوابة مالك مؤقتة على الويب (`BROWSER_CHAT_ACCESS_CODE`) إلى حين وصول الحسابات (B2). تفاصيل SSRF وحارس التحويلات وما لم يُثبَت على Browserbase الحقيقي: `docs/CHAT-BROWSER.md`.
12. (CHAT-BROWSER-2) **تحكم تفاعلي** (`/internal/v1/browser/tasks/{id}/actions|finish`) داخل «نطاق مختبر» `BROWSER_INTERACTIVE_SCOPES` (مضيف + بادئة مسار، فارغ افتراضيًا = مطفأ)؛ محدِّدات منظَّمة بلا selectors خام، موافقة صريحة مربوطة ببصمة العنصر لكل خطوة تغيّر بيانات، حظر نهائي للدفع/الحذف/الدخول/الحسابات/كلمات المرور/رفع الملفات، والنص المكتوب لا يُسجَّل. التفاصيل والمخاطر المعروفة: `docs/CHAT-BROWSER-2.md`.

راجع `docs/B1-SECURITY-REVIEW.md` لضوابط الجلسات وRLS وتوقيع الخدمات.
