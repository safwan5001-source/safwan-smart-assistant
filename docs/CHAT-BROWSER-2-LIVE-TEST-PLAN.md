# خطة الاختبار الحي الواحد على Browserbase — **للمراجعة والموافقة فقط، لم تُنفَّذ**

> **الحالة:** مسودة بانتظار موافقة المالك على **الخطة والنطاق**. لا يُنشأ أي مورد، ولا تُستخدم أي مفاتيح، ولا يُشغَّل أي شيء قبل الموافقة الصريحة. لا Railway ولا Vercel ولا أسرار الإنتاج ولا `BROWSER_INTERACTIVE_SCOPES` في أي بيئة إنتاج.

## 1) ما نريد إثباته (وما لا نريده)
| # | السؤال | الجواب المطلوب من التجربة |
|---|---|---|
| Q1 | هل تتسرب قنوات `prerender` و`preconnect` وTLS-SNI (`meta refresh`/`Refresh`/`Link`/iframe) على Browserbase **بلا** ضبط خروج؟ | ضابط تحكم: يؤكد أن المحاكاة المحلية تعكس الواقع |
| Q2 | هل تمرّ **كل** حركة جلسة Browserbase عبر وكيل خارجي نملكه (بلا `domainPattern`)؟ بما فيها WebSocket وprefetch/prerender/preconnect وDNS؟ | سجل الوكيل يرى كل محاولة، ولا شيء يصل إلى مجمّع الكاناري مباشرة |
| Q3 | هل تُطبَّق `allowedDomains`/`riskPolicyId` على التنقل/التحويل/`meta refresh` (طبقة إضافية)؟ | نتيجة منفصلة لكل منهما (لا نبني عليهما وحدهما) |
| Q4 | هل يعمل **اعتراض CDP Fetch والـCSP** عن بُعد (حقن CSP عند مرحلة الاستجابة، بوابة الآثار) وهل يتصرف `connectOverCDP` كما محليًا؟ | مصفوفة القنوات نفسها تُعاد على Browserbase وتُقارَن بالمحلية |
| Q5 | هل تُحجب الوجهات الخاصة/الداخلية من داخل الجلسة؟ (أهداف **محلية خاصة بنا** فقط) | لا اتصال بها، ويُسجَّل ما يحدث |
| Q6 | هل تُنهى الجلسة فعلًا عند الإيقاف/المهلة؟ (`COMPLETED`) | حالة الجلسة من واجهة Browserbase + عدم بقاء جلسات `RUNNING` |
| **لا نختبر:** مواقع طرف ثالث، بيانات عمل، حسابات حقيقية، أي خدمة داخلية للمساعد أو الشركة. |

## 2) الأصول (كلها **ملك المالك** ومعزولة؛ لا يُستعمل شيء من الإنتاج)
1. **نطاق المختبر `L`** — نطاق مسجَّل مستقل (ليس نطاقًا فرعيًا للتطبيق ولا للـAPI)، يخدم `labs/browser-lab/` + **صفحات القنوات الاصطناعية** (نفس صفحات `scripts/channel-matrix.mjs`) تحت `/browser-lab/`. ثابتة، بلا كوكيز، ترويسات الأمان من `vercel.json`/مكافئها. **بلا أي بيانات.**
2. **مجمّع الكاناري `C`** — خادم تسجيل صغير نملكه على نطاق/أسماء فرعية **نملكها** (مثلًا `*.c.<نطاق-ثانٍ-نملكه>`) بشهادة wildcard؛ يسجّل: كل طلب HTTP، ترقيات WebSocket، أسماء SNI، (واختياريًا استعلامات DNS إن وُجد خادم DNS نملكه). **هو بديل «evil.test» الحقيقي** — لا طرف ثالث. بلا أي اتصال بشيء آخر.
3. **وكيل الخروج `P`** — خدمة وكيل صغيرة نملكها (قائمة سماح: `CONNECT L:443` فقط؛ رفض ما عداه بما فيه العناوين الخاصة وC؛ مصادقة؛ بلا TLS interception؛ حدود معدّل)، على **مضيف مستقل تمامًا** (لا مشروع Railway الإنتاجي؛ جهاز/حاوية مؤقتة بنطاق/IP نملكه). يسجّل كل محاولة مرفوضة.
4. **مشروع Browserbase مخصص للاختبار** + **مفتاح API مخصص** (يُلغى بعد الاختبار)، بسقف إنفاق منخفض؛ ليس مفتاح الإنتاج ولا مشروعه.
5. **المُشغِّل (Runner)** — جهاز/حاوية **مؤقتة معزولة** تشغّل `services/browser` من هذا الفرع بالعميل الحقيقي لـBrowserbase. **لا** `DATABASE_URL`، **لا** `SERVICE_AUTH_SECRET`، **لا** رموز Railway/Vercel، **لا** وصول لشبكة داخلية؛ خروج فقط إلى Browserbase API وإلى `L`/`C`/`P`. (النمط نفسه كمشغّل smoke السابق، لكن بلا مشاركة بيئة الإنتاج.)

## 3) خطوات التنفيذ (بعد الموافقة فقط) — كل جلسة ≤ 3 دقائق، ≤ 40 جلسة، سقف إنفاق مُعلَن مسبقًا
**الجولة A — ضابط (بلا ضبط خروج):** جلسة بحارس العامل الكامل **بلا** `proxies` ولا `allowedDomains`، تشغَّل عليها صفحات القنوات (≈26 سيناريو). النتيجة: ما يصل إلى `C` (HTTP/WS/SNI). يجيب Q1/Q4 ويكشف الفرق عن المحاكاة المحلية.
**الجولة B1 — `allowedDomains:[L]`:** نفس السيناريوهات. يجيب Q3 (تنقل فقط).
**الجولة B2 — `riskPolicyId`** (**فقط** إن فعّل الدعم السياسات لمشروع الاختبار؛ طلب تفعيل = قرار منفصل): نفس السيناريوهات.
**الجولة C — وكيل خارجي `P` + (`allowedDomains:[L]`):** نفس السيناريوهات + ضوابط إضافية: (i) طلب إلى **IP حرفي** يملكه `C` (بلا DNS)؛ (ii) WebSocket وWebTransport وWebRTC/STUN-UDP إلى `C` (لإثبات أن UDP/QUIC لا يتجاوز الوكيل)؛ (iii) أهداف **خاصة محلية** (`10.0.0.1`، `169.254.169.254`، `127.0.0.1` ومنافذ) داخل الجلسة لتأكيد أنها لا تُتصل بها؛ (iv) استعلام DNS لاسم تحت `C` إن توفر خادم DNS نملكه (لإثبات عدم حل الأسماء خارج الوكيل).
**الجولة D — تدفق وظيفي:** `labs/browser-lab` الحقيقي عبر العامل (بدء، كتابة، زر بموافقة، إيقاف، إنهاء) لإثبات أن الحارس لا يكسر الاستعمال المشروع مع الوكيل (+ قياس زمن/باندويدث).
**الجولة E — إيقاف/تنظيف:** إيقاف أثناء انتظار موافقة وأثناء تحميل معلّق؛ التأكد من `COMPLETED` ومن غياب جلسات `RUNNING`.

## 4) معايير النجاح / الفشل
- **نجاح الضبط الخارجي:** في الجولة C **لا شيء يصل إلى `C`** بأي قناة (HTTP، WS، SNI، IP حرفي، UDP، DNS إن قِيس)، **وكل محاولة تظهر مرفوضة في سجل `P`**، ولا اتصال بأي هدف خاص، والجولة D تعمل، والجولة E تنظّف.
- **فشل:** أي وصول لـ`C` في الجولة C، أو وجود حركة لا تمر عبر `P` (تُكتشف بحركة تصل إلى `C` دون أثر في `P`)، أو جلسة تبقى `RUNNING`، أو اتصال بهدف خاص.
- **نتيجة محايدة:** `allowedDomains`/`riskPolicyId` لا تُغلق الحركة الفرعية (متوقع من التوثيق) — لا يُحتسب فشلًا بل يُوثَّق.

## 5) شروط الإيقاف الفوري (Abort)
تجاوز سقف الإنفاق؛ أي اتصال غير متوقع بمضيف **ليس** من الأصول أعلاه؛ أي إشارة لبيانات حقيقية في السجلات؛ فشل التحقق من الوكيل بما يفتح الخروج؛ جلسة لا تنتهي بعد المهلة. الإجراء: إلغاء المفتاح فورًا، إيقاف الوكيل والمجمّع، حذف المشروع.

## 6) التراجع والتنظيف (كله خارج الإنتاج)
1) إلغاء مفتاح API المخصص وحذف مشروع Browserbase التجريبي. 2) إيقاف وحذف `P` و`C` وأي حاوية/جهاز مؤقت. 3) إزالة سجلات DNS للنطاقات التجريبية وإيقاف استضافة `L` إن كانت مخصصة للاختبار. 4) حذف أي ملف نتائج يحوي معرّفات جلسات بعد أرشفة الأدلة المنقّحة. 5) **لا يوجد شيء للتراجع عنه في الإنتاج** لأنه لا يُمَسّ. إن فشل الاختبار: يبقى الحكم `BLOCKED` وتبقى الميزة مطفأة.

## 7) الأدلة التي تُجمع وتُحفظ
ملف JSON واحد لكل جولة (مصفوفة القنوات: leak/stopped لكل سيناريو)؛ سجل `C` وسجل `P` (منقّحان من أي سر)؛ مخرجات `GET /v1/sessions/{id}` (الحالة، المدة)؛ لقطات لوحة Browserbase للجلسات المنتهية؛ تقدير التكلفة؛ إصدار Chrome المُبلَّغ عنه من الجلسة؛ تجزئة (SHA-256) للأدلة.

## 8) ما أحتاج موافقتك عليه قبل أي تنفيذ
1. **النطاق:** هل `L` و`C` و`P` أصول تملكها؟ ما أسماؤها؟ (لا أنشئ شيئًا بنفسي).
2. **مشروع/مفتاح Browserbase** مخصص للاختبار وسقف الإنفاق.
3. **المُشغِّل:** أين يعمل (جهازك/حاوية مؤقتة) — بلا أسرار إنتاج.
4. هل تُطلب من Browserbase **تفعيل سياسات التنقل** لمشروع الاختبار (الجولة B2)؟ اختياري.
5. إرسال الأسئلة الخمسة إلى دعم Browserbase (انظر `docs/BROWSERBASE-EGRESS.md` §4) قبل الاختبار.
