# Smoke-1 — جلسة Browser Mode واحدة على Browserbase (Phase 0)

**لا يعمل أي شيء سحابي من تلقاء نفسه.** الوضع الافتراضي محلي بالكامل (Chromium المحلي، بلا شبكة ولا مفاتيح). التشغيل السحابي يتطلب:
1. حساب Browserbase **Free** أنشأه صاحب الحساب (لم يُتحقق هل يطلب بطاقة ائتمان).
2. `BROWSERBASE_API_KEY` (و`BROWSERBASE_PROJECT_ID` اختياري؛ الوثائق: يُستنتج من المفتاح) كمتغيرات **بيئة** — لا في المستودع ولا argv ولا سجلات.
3. موافقته الصريحة بضبط `SMOKE1_APPROVED=yes`.

## الأوامر
```bash
cd poc/smoke1 && npm i                 # playwright-core 1.63.0 (الوضع المحلي يحتاج حزمة playwright ومتصفحاتها)
node smoke1.mjs                        # محلي: يتحقق من منطق التجربة نفسه
node mock-browserbase.test.mjs         # اختبار الكود السحابي ضد خادم Browserbase وهمي محلي (بلا حساب)
BROWSERBASE_API_KEY=… SMOKE1_APPROVED=yes node smoke1.mjs --cloud                  # التجربة الحقيقية (≈ 2–3 دقائق)
BROWSERBASE_API_KEY=… SMOKE1_APPROVED=yes node smoke1.mjs --cloud --hold-live=120   # تُبقي الجلسة ويُكتب رابط البث في out/live-url.txt (0600) لاختبار يدوي من iPhone/متصفح آخر
```
`--no-ttl-test` يحذف انتظار 65 ثانية لاختبار انتهاء الرابط.

## ما تفعله (S1…S7)
| الخطوة | الفعل | معيار النجاح |
|---|---|---|
| S1 | `POST /v1/sessions` بـ `timeout=300` و`keepAlive=false` وviewport 1280×800 ثم `connectOverCDP` | جلسة وconnectUrl (يُخفى في الإخراج) |
| S2 | تحميل نموذج الاختبار بـ `setContent` (لا استضافة) | العنوان صحيح |
| S3 | كتابة عربية/إنجليزية بـ `fill` وبـ `keyboard.type` | تطابق حرفي |
| S4 | **نقرة إرسال واحدة** ثم انتظار 3ث | العدّاد 1 ثم 1 (لا تكرار) والحمولة سليمة |
| S5 | لقطة شاشة | تُحفظ محليًا في `out/` (مُتجاهَلة من git) |
| S6 | `GET /v1/sessions/{id}/debug?expiresIn=60`، ثم جلب الرابط **بلا أي اعتماد** وفتح WebSocket بلا اعتماد، ثم بعد 65ث | **ملاحظات** وليست نجاحًا/فشلًا: هل الرابط bearer؟ هل ينتهي بالـ TTL؟ |
| S6-fresh/S7 | قبل الإغلاق يُؤخذ رابط **جديد غير منتهٍ** (بلا `expiresIn`) ويُجرَّب؛ ثم `POST /v1/sessions/{id}` بـ `{status:"REQUEST_RELEASE"}` واستعلام الحالة، ثم يُجرَّب الرابط الجديد نفسه | `COMPLETED`، والرابط الذي كان يعمل (200) صار مرفوضًا — فيقيس الإبطال لا انتهاء الـ TTL |

## حدود صريحة
- **التحكم التفاعلي** عبر Live View (نقر وكتابة من متصفح آخر/iPhone) لا يُختبر برمجيًا: نجاح فتح الصفحة أو الـ WebSocket بلا اعتماد دليل على أن الرابط bearer، لا على مستوى التحكم. يُستكمل يدويًا بـ `--hold-live`.
- الشبكة الداخلية (SEC-01) وiPhone وE2B خارج Smoke-1.
- واجهة REST كُتبت من مرجع Browserbase الرسمي (جُلب 2026-10-31) واختُبرت ضد **محاكٍ محلي** لا ضد الخدمة الحقيقية؛ أي اختلاف فعلي يظهر عند أول تشغيل مصرَّح به.

## السلامة والتكلفة
- المفتاح من البيئة فقط؛ لا يُطبع ولا يُكتب. `connectUrl` و`signingKey` وروابط البث لا تظهر في الإخراج أو التقارير (يُسجَّل المضيف وطول المسار فقط) — يتحقق منه الاختبار المحلي.
- يرفض التشغيل على الواجهة الحقيقية دون `SMOKE1_APPROVED=yes`، ويرفض أي اعتماد على argv.
- سقف 300ث للجلسة و240ث للتجربة؛ يُصدر الإفراج في `finally` حتى عند الفشل. الاستهلاك المتوقع < 5 دقائق متصفح من ساعة الخطة المجانية (1 ساعة، 15 دقيقة/جلسة، 3 تزامن حسب صفحة الأسعار الرسمية).

## رموز الخروج والحكم
| الخروج | المعنى |
|---|---|
| 0 | `verdict: passed` — كل خطوة لوحظت ونجحت |
| 1 | `verdict: failed` — خطوة فشلت (مثلًا رابط حي ما زال يعمل بعد الإغلاق) |
| 2 | رفض التشغيل (مفتاح ناقص، لا موافقة على الواجهة الحقيقية، اعتماد على argv) |
| 3 | بلغت التجربة سقف 240ث وأُجهضت (مع إغلاق الجلسة) |
| 4 | `verdict: inconclusive` — فشل نقل (مهلة/DNS/TLS/إعادة ضبط) في فحص أمني، ولم يُرصد رفض فعلي. **لا يُقرأ نجاحًا**؛ أعد التشغيل |

أخطاء Playwright/الشبكة قد تحمل رابط الاتصال بمفتاحه؛ كل رسالة تمر عبر `redact()` (إزالة الأسرار المعروفة وكل URL وكل سلسلة طويلة شبيهة بالرمز) قبل الطباعة أو الكتابة في التقرير، ويغطي ذلك اختبار فشل اتصال يحمل رابطًا سريًا.
